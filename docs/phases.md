# Implementation phases

PDD §11 defines deliverables, dependencies, exit criteria and review, subject to the revised Linux-only scope; §12 defines the applicable evidence. Implementation is authorized, but no game code, media delivery or scenario execution is established by this documentation baseline. The existing repository baseline is the title-only README. No phase is closed. Role IDs below are responsibilities in the PDD, not named assignments; people and reviewers remain unassigned.

Media production can proceed in parallel but cannot bypass the ordered campaign gates. Test fixtures do not change production prerequisites or authorize shortcuts. Earlier scenarios must remain passing; a regression reopens its gate and affected content or dependency changes invalidate evidence. Phase review identifies source revision, executable hash, content digest, evidence, defects and dependencies (PDD §11.3).

PDD phase exits include manual and production evidence. They are not implementation-change gates: from source-gates onward the implementation lane runs display-free Linux source checks; desktop, device, perceptual and performance qualification remain separate manual work. The bootstrap documentation gate is `git diff --check`, not the future `scripts/check.sh`. See [verification](verification.md).
